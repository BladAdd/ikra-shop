# Сервер: база данных, вход через Google, оплата RollyPay

Этот файл — пошаговая инструкция для запуска серверной части магазина.
Всё, что нужно от вас: создать аккаунты в трёх сервисах и вставить ключи в настройки.
Код уже написан и проверен.

---

## 0. Что где лежит

```
server/
  index.ts                 точка входа Express
  config.ts                чтение .env + проверка обязательных настроек
  db.ts                    SQLite: таблицы users / orders / payments
  middleware/security.ts   Helmet (CSP), CORS, rate-limit, защита от path traversal
  middleware/auth.ts       JWT, проверка администратора
  routes/auth.ts           Google OAuth, регистрация и вход по e-mail
  routes/orders.ts         создание и получение заказов (цены считаются на сервере)
  routes/payments.ts       создание платежа RollyPay, статус
  routes/webhook.ts        колбэки RollyPay с проверкой подписи
  routes/admin.ts          каталог и загрузка фото
  services/rollypay.ts     HTTP-клиент RollyPay + проверка HMAC
```

## 1. Локальный запуск (проверить, что всё работает)

```bash
cp .env.example .env      # затем откройте .env и заполните
npm install --legacy-peer-deps
npm run dev:server        # API на http://localhost:8080
# в отдельном терминале
python -m http.server 3000   # сайт на http://localhost:3000
```

Проверка: откройте http://localhost:8080/api/health — должно вернуться
`{"ok":true,"googleAuth":false,"rollypay":false,...}`.
Без ключей Google и RollyPay сервер работает, но вход через Google и онлайн-оплата выключены.

## 2. Google OAuth — регистрация на сайте и вход в админку

1. Откройте https://console.cloud.google.com/
2. Создайте проект, например `ikra-shop`.
3. **APIs & Services → OAuth consent screen**:
   - User type: **External**
   - App name: `Икра & Рыба`, support email — ваш
   - Scopes: `userinfo.email`, `userinfo.profile` (они входят в базовый набор)
   - Test users: добавьте свою почту, пока приложение не прошло проверку
4. **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - Application type: **Web application**
   - **Authorized redirect URIs** — добавьте оба адреса:
     - `http://localhost:8080/api/auth/google/callback` (для проверки)
     - `https://ВАШ-СЕРВИС.up.railway.app/api/auth/google/callback` (для прода)
5. Скопируйте **Client ID** и **Client secret** в `.env`:

```
GOOGLE_CLIENT_ID=123456789-abcdef.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxx
```

6. Впишите почту владельца в `ADMIN_EMAILS` — именно она получит доступ к админке:

```
ADMIN_EMAILS=vashepochta@gmail.com
```

> Если владельцев несколько — перечислите через запятую.
> Админ-права выдаются автоматически при старте сервера.

**Как покупатель входит:** кнопка «Войти» в шапке сайта → «Продолжить с Google».

## 3. RollyPay — онлайн-оплата

Документация: https://docs.rollypay.io

1. Зарегистрируйтесь на https://panel.rollypay.io и создайте кассу.
2. В карточке кассы найдите **API-ключ** (`rpk_live_...`) и **signing_secret**.
3. Заполните `.env`:

```
ROLLYPAY_API_KEY=rpk_live_xxxxxxxx
ROLLYPAY_SIGNING_SECRET=whsec_xxxxxxxx
ROLLYPAY_TEST_MODE=true       # сначала тест, потом false
```

4. После деплоя укажите в кассе **callback_url**:

```
https://ВАШ-СЕРВИС.up.railway.app/webhooks/rollypay
```

Это можно сделать через API:

```bash
curl -X PUT https://rollypay.io/api/v1/terminals/ВАШ_TERMINAL_ID \
  -H "X-API-Key: rpk_live_..." \
  -H "X-Nonce: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"callback_url":"https://ВАШ-СЕРВИС.up.railway.app/webhooks/rollypay"}'
```

### Как проверить оплату без денег

При `ROLLYPAY_TEST_MODE=true` и поле `test: true` сервер создаёт тестовый платёж.
На странице оплаты вместо QR появится кнопка **«Симулировать оплату»** — нажмите её,
и вебхук придёт так же, как в реальном сценарии. Деньги не списываются.

Проверить, что вебхук дошёл, можно в логах сервера:
`[webhook] ✅ Заказ ... оплачен (ТЕСТОВЫЙ РЕЖИМ)`.

### Безопасность вебхука

Каждый колбэк проверяется до любых действий:

- подпись `HMAC-SHA256(signing_secret, timestamp + "." + rawBody)`;
- сравнение через `timingSafeEqual` (защита от timing-атак);
- отбрасывается подпись старше 10 минут (защита от replay);
- подпись считается по **сырому** телу запроса, а не по распарсенному JSON.

Неподписанный запрос получает `403` и не меняет статус заказа.

### Статусы

| Событие RollyPay | Статус заказа |
|---|---|
| `payment.paid` | `paid` — оплачен |
| `payment.canceled` | `canceled` — отменён |
| `payment.expired` | `expired` — истёк |
| `payment.refunded` / `chargeback` | `refunded` — возврат |

## 4. Деплой на Railway

1. Зайдите на https://railway.app, создайте проект из GitHub-репозитория.
2. **Settings → Build**: команда сборки `npm run build`.
3. **Settings → Deploy**: команда запуска `npm start`.
4. **Volumes** → Add Volume, mount path `/data`.
   В переменных окружения укажите `DB_PATH=/data/shop.db`, иначе база
   потеряется при перезапуске контейнера.
5. **Variables** — добавьте всё из `.env`, плюс:

```
NODE_ENV=production
APP_URL=https://ВАШ-СЕРВИС.up.railway.app
FRONTEND_URL=https://bladadd.github.io/ikra-shop
JWT_SECRET=<48 случайных байт в hex>
```

Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

6. После деплоя откройте `/api/health` — проверьте `googleAuth: true`, `rollypay: true`.

### Сайт на GitHub Pages

Статика остаётся на GitHub Pages. Адрес API сайт определяет автоматически
(не-localhost → https-домен Railway). Если адрес другой, укажите его
в `index.html` перед подключением скриптов:

```html
<script>window.IKRA_API_URL = "https://ВАШ-СЕРВИС.up.railway.app";</script>
<script src="assets/js/api.js"></script>
```

## 5. Админка

Вкладка **«Заказы»** в админке показывает:

- сводку по статусам (сколько заказов и на какую сумму);
- список заказов с фильтром;
- состав заказа, телефон, адрес, комментарий;
- смену статуса вручную и ссылку «написать в WhatsApp» покупателю.

Заходить в раздел нужно после входа через Google (кнопка на экране входа админки).
Если сервер не запущен, админка продолжает работать в локальном режиме —
каталог и фото правятся как раньше.

## 6. Что уже защищено (аудит безопасности)

| Риск | Как закрыт |
|---|---|
| Path traversal при загрузке фото | `assertInsideRootSync` — путь обязан остаться внутри `assets/img/` |
| Перезапись каталога кем угодно | `PUT /api/admin/catalog` требует администратора или `ADMIN_API_TOKEN` |
| Подмена цены в запросе | Клиент присылает только `id` и `qty`; цены берутся из каталога на сервере |
| XSS | Весь пользовательский текст экранируется (`esc()`), заголовки Helmet + CSP |
| CSRF в OAuth | Параметр `state` сверяется с httpOnly-cookie |
| Брутфорс паролей | `express-rate-limit`: 30 попыток в минуту на вход/регистрацию |
| Подделка вебхука | HMAC + `timingSafeEqual` + окно 10 минут |
| Кража сессии | JWT в httpOnly-cookie, `Secure` + `SameSite=None` в проде |
| Утечка секретов | `.env` в `.gitignore`, при старте проверяются обязательные переменные |
| SQL-инъекции | Только параметризованные запросы `better-sqlite3` |
| Хранение паролей | bcrypt, 12 раундов; одинаковый ответ на неверный пароль и несуществующую почту |

## 7. Частые проблемы

**«Слишком много попыток входа»** — сработал rate-limit, подождите минуту.

**Оплата не открывается, заказ ушёл в WhatsApp** — RollyPay не настроен
или ключи неверные. Заказ сохранён в базе, статус `pending`.

**Google пишет «redirect_uri_mismatch»** — адрес в Google Cloud
не совпадает с `APP_URL + /api/auth/google/callback` побайтно (проверьте https и порт).

**После перезапуска пропали заказы** — не смонтирован том Railway
и/или не задан `DB_PATH=/data/shop.db`.

**Вебхук не доходит** — сервер должен быть публично доступен по https.
Локально используйте `ngrok http 8080` и пропишите ngrok-адрес в `callback_url`.
