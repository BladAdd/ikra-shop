## 1. Что это

Интернет-магазин икры и копчёной рыбы: статический фронт + админ-панель, работающая через GitHub API.
Деплой автоматический: push в main → GitHub Actions (`​.github/workflows/deploy-pages.yml`) → GitHub Pages. Деплой занимает ~40 сек, статус: `gh run list --limit 1`.

## 2. Архитектура

- **Стек**: чистые HTML/CSS/JS без фреймворков, сборка Vite (`npx vite build`), TypeScript — серверная часть (server/, компилируется в `dist-server/`).
- **Источник правды**: `data/catalog.json` — 147 товаров в 7 категориях. Генерируется скриптом `tools/build_catalog.py` из прайсов поставщика.
- **Резервная копия**: `node tools/embed_catalog.cjs` встраивает catalog.json в `assets/js/data.js` (сайт работает без сервера). Запускать после каждого изменения каталога.
- **Порядок пересборки каталога**: `python tools/build_catalog.py && node tools/embed_catalog.cjs`.
- **Сборка для Pages**: `DEPLOY_TARGET=pages npx vite build` (в Git Bash; в PowerShell эта команда не сработает — есть Known issue).
- **Проверка типов**: `npm run lint`.
- **КРИТИЧНО для сервера**: прод запускается из `dist-server/` (`npm start` → `node dist-server/index.js`). Старые фиксы и контракты (packs/промокод/доставка) НЕ работают в устаревшем dist-server. После ЛЮБЫХ правок в `server/*.ts` ОБЯЗАТЕЛЬНО пересобрать: `npm run build` (vite build && tsc -p tsconfig.server.json). На 03.11.2026 dist-server пересобран (включает фиксы S1–S8, артефакты актуальны).
- **Важно**: `data/catalog.json` правит и админка напрямую через GitHub API (коммиты «Админка: …»). Перед своим push всегда делать `git fetch` + при необходимости merge. Каталог — генерируемый файл: при конфликте брать свою версию (нашу сборку), а правки админа восстанавливать осмысленно.

## 3. Каталог и цены

- 7 категорий: hot-smoked (11), cold-smoked (43), salted (37), dried (24), caviar (6), delicacies (8), pickles (18).
- Прайсы поставщика — картинки в `tools/photo_src/client/документ*.jpg` (прайс от 22.07.2026). Документ 1 — соленья/корейские салаты (цена = стоимость фасовки, НЕ за кг!), документы 2–6 — рыба (цена за кг для весовых, за фасовку для порционных).
- Структура товара: `price` — цена продажи (за кг у весовых, за упаковку у порционных с флагом `piece:true`), `weight` — фасовка витрины, `packs` — все фасовки из прайса.
- Подписи на карточке: «за 1 кг» / «за 400 г»; подсказка «Выгоднее: …» считается в `assets/js/app.js` → `packPricePerKg()/packSavingText()`.
- Логотипы/эмодзи-полоса сверху удалены по просьбе заказчика. Логотип — SVG «рыба с икрой» (в `index.html`, и в подвале тоже).

## 4. Фото — текущий рабочий процесс

- Владелец присылает фото пачкой в `assets/img` с русскими именами, совпадающими с названием товара. Затем: сопоставить по имени → переименовать в `id товара.jpg` → прописать слот в `tools/build_catalog.py` → пересобрать.
- Заглушка: `assets/img/__NEED_PHOTO__.jpg` (табличка «ПОЧИНИ МЕНЯ»). Товар без фото имеет в `img` путь на неё; на витрине плашка «Фото нужно» (`badge-need`), лайтбокс по ней не открывается.
- Фото также грузят через админку (кнопка «Загрузить новое») — появляются коммиты «Админка: загрузка фото …» с файлами вида `name-mvxXXXX.jpg`. Их надо переименовать в `<id товара>.jpg` и поправить слот, иначе каталог ссылается на старое имя.
- **Текущий статус**: 147 товаров = 27 с фото + 120 заглушек. Список позиций-заглушек — в конце этого файла.
- Владелец сам загружает фото поэтапно. Не искать фото в интернете, не ставить «похожие» — владелец дважды жёстко браковал чужие/дублированные кадры. Либо его фото, либо заглушка.

### 8а. КРИТИЧНО — бизнес-факты (проверено по коду, на 03.11.2026)

- **Промокод теперь уезжает на сервер в заказе** (app.js → `API.createOrder({…, promo})`, обе ветки `submitOrder`, app.js:807/822). - **Цена за кг фасовок у весовых товаров = `pack.price` (НЕ делить на вес).** У весовых (`unit:"кг"`, `!piece`) `pack.price` уже цена за кг, а `pack.total` — за фасовку. `packPricePerKg` в app.js:238 возвращает `pack.price` как есть; делить на вес НЕЛЬЗЯ (это ломало подпись «/за кг» у чипов). У штучных/фасованных (`piece`) цена фасовки — `pack.total` (или `pack.price × кг`).

### 8б. Контракты данных (корзина/фасовки/промо)

- **Ключ корзины** (`caviar_cart_v1`): `"<id>"` или `"<id>::<вес фасовки>"` (напр. `sm-skumbriya-gk::3 кг`). В API-заказ из линии уходит `{ id, qty, pack: <вес фасовки> }` — сервер сам находит фасовку и считает цену (`pack.total` → иначе `pack.price × кг`), 400 при чужой фасовке.
- **Фасовка (packs)**: `[{ weight, price, total }]`, у всех 147 товаров. Для `unit:"кг"` весовых: `price` — цена за кг, `total` — за фасовку (= `price × кг`). Для `piece`/штучных: `total` — цена фасовки. Линия корзины = `pack.total × qty`.
- **Промо**: `shop.promos[]` (сейчас `[]`). `applyPromo` — чистая функция: регистронезависимо, trim, minSum-граница, percent `Math.round`, fixed капится в сумму; повторное применение перезаписывает. Промо-скидка пересчитывается при каждом изменении корзины (фикс волны 2). Промокод не переживает перезагрузку страницы (не сохраняется).
- **Доставка**: enum строк точно `Курьер по Москве и МО` / `Отправка в другой город` / `Самовывоз` — совпадает с серверным enum (строки должны быть байт-в-байт, иначе сервер вернёт 400).
